# 方案层：组合式 Agent Stud 架构

## 面向谁

内部工具。面向同时管理多个工程仓库、且每个仓库都有 Codex 管家的使用者。

## 痛点

现有整份复制模式保证了子管家完整，却把通用规则和仓库私有规则混在同一份 Skill 里：升级母版时容易碰到本地修改；本地经验又容易被误当成全局规则。使用者不得不定期人工判断要不要更新，或担心覆盖仓库约定。

## 主路径

1. 大总管从公共 core 创建一个仓库管家；通用规则和仓库规则分开放置。
2. 仓库管家工作时先遵守 core，再加载该仓库的 local rules。
3. 遇到规则缺口，管家判断它是否依赖本仓库事实。
4. 依赖本仓库时，只更新 always-owned 的 local rules，并记录 local evolution。
5. 跨仓库成立时，记录脱敏的 upstream candidate，通知大总管。
6. 大总管审查候选后才更新公共 core；未来同步只作用于 core，不触碰 local。

## 不做什么

本期不自动合并候选、不自动改任何子仓库、不运行隐式继承，也不改变已有 `$project-steward` 调用名。
